## 3. CI (DX2-0005, DX2-0006, DX2-0007)

Satu workflow: `.github/workflows/ci.yml`, trigger `push: main`, `pull_request`, `workflow_dispatch`.

- Job `test`: matrix 2 OS (ubuntu/windows) x 2 Node (20.17.0 / 22.13.0). Langkah: install
  `--frozen-lockfile --ignore-scripts` → `pnpm build` → build api → build web → smoke CLI
  (`pnpm --filter neuralforge exec node dist/main.js --version`) → `pack --dry-run` → `pnpm test` → `pnpm check`.
- Job `dom`: Chromium terisolasi, gated `WTAGENT_DOM_TESTS=1`.

**Status CI pada baseline:** `main` merah pada 5 run berturut-turut sebelum audit
(run 41951027057 s/d 41957506839). Audit awal hanya membaca job ubuntu Node 22.13.0; setelah
matrix lengkap diperiksa, kegagalan pada job lain punya akar berbeda. Tiga signature yang nyata:

1. `Error: Cannot find module '../dist/index.js' imported from packages/config-api/test/config-api.spec.ts` (`ERR_MODULE_NOT_FOUND`).
   Akar masalah: `packages/config-api` tidak ada di `references` `tsconfig.json` root, sehingga
   `pnpm build` (`tsc -b`) tidak pernah menghasilkan `dist/`-nya. Lokal lolos karena `dist/` sisa build manual.
2. `AssertionError: expected false to be true` di `packages/policy/test/path-guard.spec.ts:26`, `:31`, `:52`.
   Akar masalah: tiga asersi menandatangani semantik path Windows — kandidat relatif di-resolve terhadap
   cwd milik developer (`/project` vs cwd repo) dan root yang berbeda huruf besar/kecil dianggap di dalam —
   sedangkan cabang POSIX `isPathInside` memakai `path.relative` host yang case-sensitive.
3. `require() of ES Module .../cookie@2.0.1/... from .../light-my-request@6.8.0/lib/cookies.js not supported`
   (koleksi `apps/api/test/app.integration.spec.ts`: 40/40 test gagal dalam 415 ms) pada kedua job Node 20.17.0.
   Akar masalah: `cookie@2.0.1` ESM-only dan menyatakan `engines.node >= 22`, sementara `engines` root
   resmi mendukung `^20.17.0`. Node 20 tidak punya `require(esm)`.
4. Dua asersi `projectRoot` gagal hanya di Windows: `testDir` dari `os.tmpdir()` datang sebagai nama pendek
   8.3 (`C:\Users\RUNNER~1\...`) sedangkan app men-normalisasi lewat `fs.realpath`
   (`C:\Users\runneradmin\...`). Perilaku app benar; perbandingan test yang salah bentuk.
5. `Error: Could not acquire the NeuralForge session lock at ...\.neuralforge-state.lock.` pada job
   windows/Node 20.17.0 (`test/session.test.js > a recycled live pid does not make a crashed state lock permanent`).
   Akar masalah: `acquirePersistenceLock` berjalan di deadline 2 detik, sedangkan pengecekan owner daur-ulang
   memicu PowerShell dengan timeout 1,5 detik. Cold start PowerShell menghabiskan seluruh budget,
   `processStartTimeMs` menjadi `null`, pid hidup dianggap bukan hasil daur ulang, dan lock milik proses crash
   permanen. Ini defect produksi, bukan sekadar flake test.

**Perbaikan yang dibuat** (bukan membalik assertion demi hijau, dan tidak mengubah semantik guard):

| Commit | Isi |
|---|---|
| `2d6c476` | `path-guard.spec.ts`: asersi diturunkan dari `process.cwd()`/`it.runIf` + `config-api.spec.ts` impor `src` |
| `e1bd9b5` | `pnpm-workspace.yaml`: override scoped `light-my-request>cookie: ^1.0.2` (terkunci ke 1.1.1; tidak ada konsumen lain yang butuh v2) + `app.integration.spec.ts` memakai `fs.realpath(testDir)` |
| `1cf3f96` | `session`: budget acquire 2s → 8s dan timeout PowerShell 1.5s → 5s, agar recovery lock daur-ulang punya ruang satu lookup start-time |

**Hasil verifikasi:** run 41960387932 pada SHA `1cf3f96` → `success`, kelima job hijau
(`dom`, ubuntu/windows × Node 20.17.0/22.13.0). Baseline `main` kembali hijau.

## 8. Temuan tindak lanjut (bukan bagian status M00)

1. `config-api` dan 8 package lain berada di luar build graph root → `pnpm build` dan `pnpm check`
   tidak pernah memverifikasi tipe/dist mereka. Kandidat perbaikan: M03.
2. Dua identitas env (`NEURALFORGE_*` vs `WTAGENT_*`) dan dua scope package (`@dx-platform/*` vs
   `neuralforge`) → M01.
3. `.next` ter-track → M01 (DX2-0037/0038).
4. `packages/diagnostics` dan `packages/security` adalah direktori yatim tanpa manifest, tetapi
   `packages/diagnostics/test/**` tetap dijalankan root vitest → perlu diputuskan: jadikan package atau keluarkan dari include.
5. Tidak ada source migration untuk skema DB → M05.
6. **Lima filter CI menunjuk package yang tidak ada.** `Build API`, `Build web app`, dan ketiga langkah
   di job `dom` memakai `@neuralforge/api`, `@neuralforge/web`, `@neuralforge/tests`. pnpm membalas
   `No projects matched the filters` dengan **exit code 0**, jadi langkah-langkah itu menjadi no-op dan
   job tetap hijau. Artinya sejak awal CI tidak pernah membangun `apps/api` dan `apps/web`, dan 14 test
   DOM/rendered-text **tidak pernah benar-benar dijalankan di CI**. Diperbaiki di batch M01 pertama.
7. `packages/cli/src/startup-notices.ts` mengambil `NOTICES_URL` dari
   `raw.githubusercontent.com/XiXian42/neuralforge/main/notices.json`, yaitu repository pihak ketiga,
   bukan fork ini. CLI yang kita publikasikan karena itu memanggil aset milik upstream saat startup.
   Tidak diubah di batch ini: memindahkan URL adalah keputusan produk (perlu host notices sendiri atau
   mematikan fitur), dan perubahan senyap bisa membuat fitur 404.
8. `packages/security/src/{audit-log.ts,security-headers.ts}` ter-commit tetapi tidak punya
   `package.json`, tidak masuk `pnpm-workspace.yaml`, tidak masuk `references` root, dan tidak tercakup
   `vitest.config.ts` → source aktif yang tidak pernah di-build dan tidak pernah diuji.
   (`packages/diagnostics/` berbeda: sengaja di-ignore oleh `.gitignore`, jadi bukan bagian repo.)
